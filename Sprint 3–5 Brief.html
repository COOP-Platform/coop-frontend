Sprint 3–5 Brief

COOP Platform · Combined sprint · Thu 29 Oct – Wed 11 Nov 2026 · Prepared 26 Oct 2026 by the Product Owner

Goal: by the end of this sprint, Les Cousins runs its meetings and its money on the platform instead of WhatsApp. A contribution goes from a member's proof upload to Treasurer confirmation to the dashboard. A meeting goes from scheduling to attendance to final minutes.

Sprint goals

1. Meetings replace WhatsApp

Schedule a meeting with an agenda, take attendance with a live quorum check, write minutes with decisions and action items. Final minutes can't change.

Must

2. Contributions end-to-end

Member records a payment with proof, the Treasurer confirms or rejects it, and totals update on their own. Members see their own history and statement.

Must

3. Money is visible

Expenses with receipts, one dashboard with balance and outstanding, a full ledger, and monthly reports.

Must Ledger + reports: Should

4. Community informed

Announcements, events with RSVP, meeting and attendance reports. Built only if the Must work closes early.

Frontend ↔ backend contract

This is the agreement both sides build against so the frontend doesn't wait on the backend. It is a proposal to confirm at sprint planning; the OpenAPI spec published by the backend is the final source of truth.

How we work with the contract

  • Backend publishes the OpenAPI spec for Must endpoints on day 1–2, before the implementation is finished.
  • Frontend generates a typed client and mocks from that spec, and builds pages against the mocks.
  • Any change to a request or response shape goes through a pull request that both a backend and a frontend developer approve.
  • Backend merges and deploys endpoint by endpoint to staging, not in one drop at the end.

Shared rules

TopicRule
Base URL/api/v1, JSON everywhere except file uploads (multipart/form-data) and PDF downloads
AuthAuthorization: Bearer <JWT> from Sprint 1–2. Role checks are enforced on the server; the UI only hides buttons.
MoneyIntegers in RWF, no decimals, never floats. Example: "amount": 50000
DatesISO 8601 in UTC from the API (2026-11-11T08:00:00Z). The frontend displays Africa/Kigali time.
Lists?page=1&page_size=20 → { "items": [...], "total": 42, "page": 1, "page_size": 20 }
ErrorsHTTP status + { "error": { "code": "QUORUM_NOT_REACHED", "message": "...", "details": {} } }
CorrectionsMoney records are never deleted. Mistakes are fixed with a reversal that requires a reason.
FilesProof of payment, receipts and minutes are private. The API returns short-lived signed URLs, never public links.

Status values (shared enums)

Contribution : PENDING | PAID | REJECTED | REVERSED
Expense      : RECORDED | REVERSED
Meeting      : UPCOMING | COMPLETED | CANCELLED
Attendance   : PRESENT | ABSENT | EXCUSED
Minutes      : DRAFT | FINAL
Payment method: MTN_MOMO | AIRTEL_MONEY | BANK_TRANSFER | CASH
